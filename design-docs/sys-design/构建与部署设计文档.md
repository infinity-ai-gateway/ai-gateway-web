# AI Gateway Web 构建与部署设计文档

## 1. 设计目标

- 定义开发、构建、部署的完整流程。
- 统一 webpack 配置与开发服务器行为。
- 支持本地开发代理后端 API，实现前后端分离开发。
- 生产构建输出静态资源，由 Nginx/CDN 托管。

## 2. 构建脚本

`package.json` 中定义的脚本：

| 脚本 | 命令 | 说明 |
|------|------|------|
| `start` | `node configs/dev-server.js $PORT` | 启动开发服务器。 |
| `build` | `node configs/build.js` | 生产构建。 |
| `test` | `cross-env BABEL_ENV=test karma start test/unit/karma.conf.js` | 运行单元测试。 |
| `lint` | `eslint --ext .js,.vue ./ --quiet --fix` | 代码检查与自动修复。 |

## 3. 配置文件结构

```
configs/
├── config.js            # 开发/生产环境公共配置
├── build.js             # 生产构建入口脚本
├── dev-server.js        # 开发服务器入口脚本
├── devProxy.js          # 开发时代理配置
├── dev-client.js        # 开发客户端热更新配置
├── webpack.base.conf.js # webpack 基础配置
├── webpack.dev.conf.js  # webpack 开发配置
├── webpack.prod.conf.js # webpack 生产配置
└── webpack.test.conf.js # webpack 测试配置
```

## 4. 基础配置（`webpack.base.conf.js`）

### 4.1 入口与输出

```js
entry: {
  app: './src/main.js',
}
output: {
  path: config.build.assetsRoot,
  publicPath: config.build.assetsPublicPath / config.dev.assetsPublicPath,
  filename: '[name].js',
  chunkFilename: '[name].js',
}
```

### 4.2 Resolve 别名

| 别名 | 指向 |
|------|------|
| `vue$` | `vue/dist/vue.common.js` |
| `vue-router$` | `vue-router/dist/vue-router.common.js` |
| `@` | `src/` |
| `src` | `src/` |
| `common` | `src/components/` |

### 4.3 Loader 规则

| 文件类型 | Loader |
|----------|--------|
| `.vue` | `vue-loader` |
| `.js` | `babel-loader`（含缓存） |
| `.css` | `vue-style-loader` / `MiniCssExtractPlugin.loader` + `css-loader` |
| `.less` | `vue-style-loader` / `MiniCssExtractPlugin.loader` + `css-loader` + `less-loader` |
| 图片/字体 | webpack 5 `asset` 类型，按大小内联或输出到 `static/` |

### 4.4 插件

- `VueLoaderPlugin`：确保 `.vue` 文件正确解析。

## 5. 开发环境配置

### 5.1 开发服务器（`dev-server.js`）

- 基于 `express` + `webpack-dev-middleware` + `webpack-hot-middleware`。
- 默认监听端口 `8085`，可通过 `PORT` 环境变量覆盖。
- 使用 `morgan` 输出请求日志。
- 通过 `body-parser` 解析 JSON 与 URL 编码请求体。
- 自动打开浏览器访问 `http://localhost:<port>/?em`。
- 使用 `connect-history-api-fallback` 支持 `history` 模式路由。

### 5.2 代理配置（`devProxy.js`）

开发时将 `/open-api/v1` 开头的请求代理到后端服务：

```js
proxy: {
  path: ['/open-api/v1'],
  option: {
    target: 'http://127.0.0.1:8183',
    changeOrigin: true,
    headers: { Cookie: false }
  }
}
```

- 代理配置在 `config.js` 中加载，开发服务器读取 `config.dev.proxyTable` 动态创建代理中间件。

### 5.3 开发配置（`webpack.dev.conf.js`）

- 启用 `eval-cheap-module-source-map` 或类似 source map。
- 启用热更新（HMR）。
- CSS 不提取，使用 `vue-style-loader` 注入。

## 6. 生产环境配置

### 6.1 构建脚本（`build.js`）

```
1. 设置 NODE_ENV=production
2. 清理 dist/static 目录
3. 复制 static/ 目录资源到 dist/static
4. 执行 webpack 生产构建
5. 输出构建统计信息
6. 若存在错误则退出进程
```

### 6.2 生产配置（`webpack.prod.conf.js`）

- 使用 `MiniCssExtractPlugin` 提取 CSS。
- 使用 `CssMinimizerPlugin` 压缩 CSS。
- 使用 `TerserPlugin` 压缩 JS。
- 启用 `compression-webpack-plugin` 生成 gzip 资源。
- 不生成 source map（`productionSourceMap: false`）。
- 输出到 `dist/static/`。

### 6.3 输出目录

```
dist/
├── index.html
└── static/
    ├── app.js
    ├── css/
    ├── img/
    └── fonts/
```

## 7. 环境配置（`config.js`）

| 配置项 | 开发环境 | 生产环境 |
|--------|----------|----------|
| `NODE_ENV` | `development` | `production` |
| 端口 | `8085` | - |
| 静态资源子目录 | `static` | `static` |
| 静态资源公共路径 | `/` | `/` |
| 是否提取 CSS | 否 | 是 |
| source map | 是 | 否 |
| gzip | 否 | 是 |

## 8. 部署方式

生产构建产物为纯静态文件，部署方式：

1. 执行 `npm run build` 生成 `dist/`。
2. 将 `dist/` 部署到 Nginx 或 CDN。
3. 配置 Nginx 将所有路由回退到 `index.html`，以支持 `history` 模式。
4. 静态资源可配置长期缓存（文件名不含 hash，当前需全量刷新缓存）。

示例 Nginx 配置：

```nginx
server {
  listen 80;
  root /path/to/dist;
  index index.html;

  location / {
    try_files $uri $uri/ /index.html;
  }

  location /open-api/v1 {
    proxy_pass http://ai-gateway-api;
  }
}
```

## 9. 代码规范

- ESLint 配置检查 `.js` 与 `.vue` 文件。
- Prettier 插件负责格式化。
- 提交前建议运行 `npm run lint`。

## 10. 构建优化

| 优化点 | 实现方式 |
|--------|----------|
| 代码分割 | 按路由 `require.ensure` 懒加载。 |
| gzip 压缩 | `compression-webpack-plugin`。 |
| CSS 提取与压缩 | `MiniCssExtractPlugin` + `CssMinimizerPlugin`。 |
| JS 压缩 | `TerserPlugin`。 |
| 图片内联 | webpack 5 `asset` 类型，小于 10KB 内联。 |

## 11. 扩展构建能力 checklist

- [ ] 评估是否需要修改 `webpack.base.conf.js` 或 `webpack.prod.conf.js`。
- [ ] 开发环境变更优先修改 `webpack.dev.conf.js` 与 `dev-server.js`。
- [ ] 代理变更修改 `devProxy.js`，并在 `config.js` 中生效。
- [ ] 更新本文档说明新的构建流程或配置项。
- [ ] 确保 `npm run build` 与 `npm run lint` 通过。
