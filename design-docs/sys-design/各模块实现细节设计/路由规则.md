# RouteTable 模块细节设计

## 1. 模块定位

`RouteTable` 是路由规则管理的实现模块，替代了原有的 `Routes`（默认路由规则）和 `AIRouteRules`（高级 AI 路由规则）模块。支持按全局（global）、Entity、API-Key 三种维度管理路由规则，使用 BFE 条件表达式匹配请求，并转发到目标集群。

> 历史说明：原 `Routes` 和 `AIRouteRules` 模块已在 UI 优化中删除，路由路径 `/router` 和 `/ai-rule` 已被 `/route-tables` 替代。

## 2. 路由与入口

| 路由 | name | 组件 | 说明 |
|------|------|------|------|
| `/route-tables` | `AdvanceRouteRule.list` | `modules/RouteTable/index.vue` | 路由表列表页 + 详情容器。 |

内部组件：

- `modules/RouteTable/index.vue`：列表视图与详情视图的容器。
- `modules/RouteTable/components/RouteRules.vue`：规则列表 + 编辑/查看模式切换。
- `modules/RouteTable/components/RuleForm.vue`：规则新增/编辑表单。
- `modules/RouteTable/components/RuleView.vue`：规则只读展示。
- `components/Expression/index.vue`：BFE 条件表达式编辑器组件。

## 3. 页面结构

### 3.1 列表视图

- 使用 `pageTable` 展示路由表列表，列：`id`、`type`（global/entity/apikey）、`owner`（Entity 时解析为名称）、`enabled`（Switch 切换）、操作列（查看）。
- 点击行进入详情视图（`detailVisible=true`）。
- 支持 URL query 深链接：`?type=global&owner=&rule=xxx` 可直接打开详情页并预置规则名搜索。

### 3.2 详情视图（RouteRules）

- 切换 `mode`：`view`（查看态）↔ `edit`（编辑态）。
- 查看态：展示规则列表，操作列含「查看」按钮。
- 编辑态：展示规则列表，操作列含「编辑」、「删除」按钮；顶部有「添加规则」按钮和「提交并生效」按钮。
- 规则列表列：序号（`index`）、规则名（`name`）、条件表达式（`Cond`）、目标集群（`targets` Tag 列表）、操作。
- 支持搜索过滤（`pageTable` 内置前端搜索）。

### 3.3 规则编辑抽屉（RuleForm）

- Drawer 宽度 60%。
- 表单字段：规则名称、条件表达式（Expression 组件）、目标集群列表（ClusterName + Model + Weight）。
- 目标列表可动态增删，每条含集群选择、模型选择（可留空表示透传）、权重。

### 3.4 规则查看抽屉（RuleView）

- Drawer 宽度 50%。
- 只读展示：规则名称、条件表达式（等宽字体）、目标集群（Tag 列表，格式 `ClusterName/Model: Weight%`）。

## 4. 组件清单

| 组件 | 职责 | 关键 Props | 事件 |
|------|------|------------|------|
| `index.vue` | 列表 + 详情容器 | — | — |

## 5. 表单字段与校验

| 字段 | 校验 | 说明 |
|------|------|------|
| `name` | 必填；1-64 字符；`/^[a-zA-Z0-9]([a-zA-Z0-9._-]{0,62}[a-zA-Z0-9])?$/`（字母数字开头结尾，中间可含 `._-`） | 规则名称。 |
| `Cond` | 必填；自定义 `validateCond`（空值报错；`condErrmsg` 非空报错） | BFE 条件表达式，通过 `PATCH /expression/verify` 实时验证。 |
| `targets[].ClusterName` | 必填 | 目标集群，Select filterable。 |
| `targets[].Model` | 可选 | 目标模型，Select filterable allow-create clearable，留空表示透传。 |
| `targets[].Weight` | 自定义校验：非空、`Number(value)` 非 NaN、0-100 | 转发权重。 |

### 5.1 额外校验（handleSubmit 中执行）

- 表单整体校验通过后继续。
- **权重总和校验**：所有 targets 的 Weight 之和必须等于 100。
- **目标去重校验**：`(ClusterName, Model)` 组合不可重复。
- **至少一个目标**：`targets.length === 0` 时报错。

### 5.2 提交时数据清洗

- 每条 rule 删除 `index`、`_index`、`_rowKey`、`fallbacks` 等 UI 内部字段。
- RuleForm 提交时删除 `condErrmsg`、`fallbacks`。

## 6. 数据流

```
RouteTable/index.vue (列表页)
    ├─ mounted → fetchData() (GET /route-tables) + fetchEntityNames() (GET /entities) + openFromQuery()
    │
    ├─ onView(row) → 设置 currentType/currentOwner → detailVisible=true
    │   ↓ 传 props 给 RouteRules
    │
    └─ RouteRules.vue (详情/编辑子组件)
          ├─ mounted → fetchClusters() (GET /clusters) + fetchRules()
          │   ├─ global → GET /global-route-rules
          │   ├─ entity → GET /entities/{owner}
          │   └─ apikey → GET /api-keys/{owner}
          │   → this.enabled, this.rules → refreshRuleIndex() → applyInitialFilter()
          │
          ├─ enterEditMode() → originalRules = cloneDeep(rules), originalEnabled = enabled
          │
          ├─ RuleForm.vue (编辑抽屉)
          │   ├─ GET /clusters → modelServices
          │   ├─ Expression → PATCH /expression/verify (实时验证)
          │   └─ @submit → onRuleFormSubmit() → rules.push/splice → refreshRuleIndex()
          │
          ├─ RuleView.vue (查看抽屉, 仅 view 模式)
          │
          └─ submitRules() (点击"提交并生效")
                ├─ 检查规则名重复
                ├─ buildPayload()
                │   ├─ global: {enabled, rules}        → PUT  /global-route-rules
                │   └─ entity/apikey: {route_rules: {enabled, rules}}
                │                                        → PATCH /entities/{owner} 或 /api-keys/{owner}
                └─ 成功 → mode='view', $emit('submit') → 父组件 fetchData()
```

- 列表页通过 `detailVisible` 布尔值切换列表视图与详情视图。
- `RouteRules` 内部通过 `mode`（`view`/`edit`）切换查看与编辑模式。
- `originalRules` 快照实现脏检查（`isDirty` computed：比较 `enabled` 和 `JSON.stringify(rules)` 与快照差异）。
- 离开详情页时若 `isDirty` 为 true，弹 `$Modal.confirm` 确认框（`onCloseRequest`、`beforeRouteLeave`、面包屑 watcher 三处触发）。

### 7.1 方法选择逻辑

```js
getUpdateMethod() {
  return this.type === 'global' ? 'put' : 'patch';
}
```

- **global** 类型：`PUT /global-route-rules`，body 为完整 `{enabled, rules}`。
- **entity** 类型：`PATCH /entities/{owner}`，body 为 `{route_rules: {enabled, rules}}`。
- **apikey** 类型：`PATCH /api-keys/{owner}`，body 为 `{route_rules: {enabled, rules}}`。

> 注：原 `ai-route-rules` 端点已被 `route-tables` + `global-route-rules` + 各资源自身的 `route_rules` 字段替代。

## 8. 边界情况与注意事项

- **脏检查与离开确认**：`isDirty` 比较当前 `enabled` 和 `JSON.stringify(rules)` 与 `originalRules` 快照的差异，有未提交变更时弹确认框（三处触发：返回按钮、路由离开、面包屑清空）。
- **切换启用状态时的规则保护**：切换 enabled 前先 `fetchFullRules(row)` 获取完整规则，再将 `newEnabled` 和完整 `rules` 一起提交，防止只传 `enabled` 导致原有规则被覆盖清空。防抖：`loading` 为 true 时忽略点击。
- **规则名重复检查**：提交前检查所有规则名是否重复，重复则提示并中止。
- **`enabled` 布尔值与字符串转换**：Select 绑定 `enabledValue`（字符串 `'true'`/`'false'`），实际逻辑用 `enabled`（布尔），watcher 同步。
- **`applyInitialFilter` 的双重 nextTick**：`pageTable` 的 `tableData` watcher 会清空 `searchValue`，需在其执行后再预置，使用双层 `$nextTick` 嵌套确保时序正确。
- **集群选择后清空模型**：切换目标集群时清空 `Model` 字段，防止模型与集群不匹配。
- **同一集群多目标允许**：不排除已选集群，仅通过 `validateDuplicate` 校验 `(ClusterName, Model)` 组合唯一性。
- **URL query 深链接**：支持 `type`/`owner`/`rule` 参数，`type` 必须在 `TYPE_MAP`（`global`/`entity`/`apikey`）中，`rule` 作为 `initialFilter` 预置规则名搜索。
- **面包屑导航**：通过 `store.setBreadcrumbTitle(title, 'AdvanceRouteRule.list')` 设置，格式 `路由规则 - {类型} / {属主}`，点击面包屑跳回列表，`beforeDestroy` 时清空。
- **不支持的拖拽排序**：`pageTable` 支持 `draggable` prop 但当前未传递，拖拽排序禁用。i18n 中仍保留旧文案但未被引用。
