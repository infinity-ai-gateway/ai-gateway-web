# RouteTable 模块细节设计

## 1. 模块定位

`RouteTable` 统一管理三级路由表：**Global**、**Entity**、**API-Key**。列表页分页展示所有路由表；进入详情后以内联方式编辑该表下的路由规则。规则支持加权 `targets` 与降级 `fallbacks`，条件表达式由 `Expression` 组件编辑（含 `req_body_json_prefix_in`、`req_body_larger_than`、`req_body_less_than`）。

已废弃的 `modules/Routes`、`modules/AIRouteRules` 不再使用；路由 `name` 仍为 `AdvanceRouteRule.list`，路径为 `/route-tables`。

## 2. 路由与入口

| 路由 | name | 组件 | 说明 |
|------|------|------|------|
| `/route-tables` | `AdvanceRouteRule.list` | `modules/RouteTable/index.vue` | 路由表列表；query `type` / `owner` / `rule` 可直达详情。 |

内部组件：

- `RouteTable/index.vue`：列表 + 详情切换。
- `RouteTable/components/RouteRules.vue`：某张表的规则列表、启停、提交。
- `RouteTable/components/RuleForm.vue`：单条规则表单（条件、targets、fallbacks）。
- `RouteTable/components/RuleView.vue`：单条规则只读详情。

## 3. 页面结构

### 3.1 列表页

- `pageTable` 开启 `server-pagination`，请求 `GET route-tables`（`page` / `page_size` + type/owner/enabled 筛选）。
- 列：类型（Global / Entity / API-Key）、归属、启用状态、操作（查看、启停）。
- Entity 类型的 owner 通过 `GET entities` 解析为名称。

### 3.2 详情 / 规则编辑

- 进入详情后覆盖面包屑（`store.setBreadcrumbTitle`）。
- `RouteRules` 支持查看 / 编辑；未保存离开时二次确认。
- 行内新增、编辑、查看、删除规则；整表提交一次生效。

## 4. 组件清单

| 组件 | 职责 | 关键 Props | 事件 |
|------|------|------------|------|
| `index.vue` | 列表分页、打开详情、启停 | — | — |
| `RouteRules.vue` | 某张表的规则 CRUD 与提交 | `type`、`owner`、`ownerName`、`initialData`、`initialFilter` | `close`、`submit` |
| `RuleForm.vue` | 单条规则表单 | 规则数据、集群列表 | `submit` |
| `RuleView.vue` | 单条规则只读 | `rule` | — |

## 5. 表单字段与校验

规则字段统一 snake_case，与 OpenAPI 对齐：

| 字段 | 校验 | 说明 |
|------|------|------|
| `name` | 必填；同表内不重复 | 规则名称。 |
| `cond` | 表达式校验 | 匹配条件；`Expression` 组件编辑。校验失败时**仅**外层 FormItem 展示错误，组件内不重复渲染 error 文本。 |
| `targets[]` | `cluster_name` 必填；`weight` 之和为 100 | 转发目标；`model` 可空表示透传。 |
| `fallbacks[]` | 可选 | 降级目标；无 weight。 |
| `(cluster_name, model)` | `targets` 内部、`fallbacks` 内部、以及两者之间均不可重复 | 交叉去重。 |

表达式 `body` 维度新增 `req_body_json_prefix_in(jsonpath, patterns, foldCase)`，用于按请求体 JSON 字段前缀匹配（如 `req_body_json_prefix_in("model", "openrouter/", false)`）。

## 6. 数据流

```
RouteTable/index.vue
    ├─ GET /route-tables → 分页列表
    ├─ 查看 → RouteRules.vue
    │     ├─ Global：GET/PUT /global-route-rules  （body: { enabled, rules }）
    │     ├─ Entity：GET/PATCH /entities/{id}     （body: { route_rules: { enabled, rules } }）
    │     └─ API-Key：GET/PATCH /api-keys/{id}    （同上嵌套 route_rules）
    │           └─ RuleForm / RuleView
    └─ 列表启停：拉取完整规则后 PUT/PATCH，只改 enabled
```

## 7. OpenAPI 消费映射

| 组件 | 方法 | 相对 URL | 说明 |
|------|------|----------|------|
| `index.vue` | `GET` | `route-tables` | 分页列表。 |
| `index.vue` | `GET` | `entities` | 解析 Entity 名称。 |
| `RouteRules.vue` | `GET` | `clusters` | 目标/降级集群。 |
| `RouteRules.vue` | `GET` / `PUT` | `global-route-rules` | Global 表。 |
| `RouteRules.vue` | `GET` / `PATCH` | `entities/{id}`、`api-keys/{id}` | 嵌套 `route_rules`。 |
| `RuleForm.vue` | `GET` | `clusters` | 集群与模型下拉。 |

## 8. 边界情况

- 路由 `name` 保持 `AdvanceRouteRule.list`，与后端导航元数据 `id` 一致，路径已从 `/ai-rule` 改为 `/route-tables`。
- 启停切换必须带上完整 `rules`，避免后端把规则清空。
- 从 Entity / API-Key 页可带 query 跳入对应路由表详情。
