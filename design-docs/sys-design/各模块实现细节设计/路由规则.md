# AIRouteRules 模块细节设计

## 1. 模块定位

`AIRouteRules` 是**高级 AI 路由规则**的实现模块，支持更细粒度的匹配条件（域名、路径、Header、方法、模型）与动作转发。当前代码已完整实现，但**路由尚未挂载**，`/ai-rule` 当前仍由 `Routes` 模块承载。

## 2. 路由与入口

| 路由 | name | 组件 | 说明 |
|------|------|------|------|
| `/ai-rule`（计划） | `AdvanceRouteRule.list` | `modules/AIRouteRules/index.vue` | 当前未实际挂载。 |

内部入口：

- `modules/AIRouteRules/index.vue`：顶部「提交并生效」+ Tab 容器。
- `modules/AIRouteRules/Rules/index.vue`：规则表格与抽屉向导。
- `modules/AIRouteRules/Rules/components/index.vue`：2 步向导容器。
- `modules/AIRouteRules/Rules/components/Rules.vue`：规则配置表单。
- `modules/AIRouteRules/Rules/components/Review.vue`：复核只读展示。

## 3. 页面结构

### 3.1 列表页

- 展示字段：执行顺序、规则名、域名、路径匹配、Method、Header 匹配、模型匹配、目标集群、操作。
- 顶部「添加路由规则」按钮打开抽屉。
- 行内支持编辑、删除（查看按钮引用未定义，实际未渲染）。

### 3.2 新建/编辑抽屉

- 2 步向导：规则配置 → 复核。
- `mode` 支持 `add` / `edit` / `view`。
- 每一步「本地保存」后回写父级 `draftRules`，最终由父级 `PATCH` 整包提交。

## 4. 组件清单

| 组件 | 职责 | 关键 Props | 事件 |
|------|------|------------|------|
| `index.vue` | 入口 + 提交按钮 | — | — |
| `Rules/index.vue` | 列表 + Drawer | `rules` | `update:forward_rules` |
| `Rules/components/index.vue` | 2 步向导 | `mode`、`currentRule`、`ruleNames` | `submitForm`、`cancel` |
| `Rules/components/Rules.vue` | 规则表单 | `clustersData`、`basic`、`isAdd`、`ruleNames` | 暴露 `validate` / `getFormData` |
| `Rules/components/Review.vue` | 复核 | `data` | — |

## 5. 表单字段与校验

| 字段 | 校验 | 说明 |
|------|------|------|
| `name` | `CommonNameCheck` + 重名检测 | 规则名称。 |
| `domain` | 可选 FQDN | 域名匹配。 |
| `path_filter` | `match_mode` 与 `path` 同填或同空 | 路径匹配。 |
| `header_filters` | 每行 key/value/match_mode 全填或全空 | Header 匹配。 |
| `method_filter` | 可选 | 请求方法。 |
| `model_filter` | 有 `name` 时 `pattern` 必填 | 模型匹配。 |
| 匹配条件 | 至少填 domain / path / header / method / model 之一 | 防止空规则。 |
| `expect_action.action` | 必填 | 执行动作。 |
| `expect_action.forward.cluster_name` | `action === 'forward'` 时必填 | 目标集群。 |

提交结构示例：

```json
{
  "expect_action": {
    "forward": {
      "cluster_name": "xxx"
    }
  }
}
```

## 6. 数据流

```
AIRouteRules/index.vue
    ├─ GET /ai-route-rules → rules = Data
    ├─ 传给 Rules/index.vue 作为 props
    │     └─ Drawer 内 2 步向导
    │            ├─ Rules.vue 提供 validate/getFormData
    │            └─ Review.vue 展示
    │     └─ $emit('update:forward_rules') 回写 draftRules
    └─ 点击「提交并生效」→ PATCH /ai-route-rules → { rules: draftRules }
```

## 7. OpenAPI 消费映射

| 组件 | 方法 | 相对 URL | 说明 |
|------|------|----------|------|
| `AIRouteRules/index.vue` | `GET` | `ai-route-rules` | 读取完整 `rules` 数组。 |
| `AIRouteRules/index.vue` | `PATCH` | `ai-route-rules` | 提交 `{ rules: draftRules }`。 |
| `Rules/components/index.vue` | `GET` | `clusters` | 仅取 `ready` 集群。 |

## 8. 边界情况与注意事项

- 本模块与 `Routes` 模块消费同一 `ai-route-rules` 端点，但请求体字段不同（`rules` vs `forward_rules`）。
- 当前路由未启用，启用前需确认后端与产品侧希望使用哪种规则格式。
- `rulesViewBtn` 未定义，查看模式 UI 不完整，启用前需补齐。
- 列表不支持拖拽排序，与 `Routes` 默认转发规则的设计不同。
