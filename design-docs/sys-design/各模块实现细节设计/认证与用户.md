# 认证与用户模块细节设计

## 1. 模块定位

本模块覆盖前端所有与**身份认证**和**用户/Token 管理**相关的界面：

- **登录**（`Login`）：管理员入口，获取并保存会话。
- **首页**（`Home`）：登录后欢迎页，展示当前用户。
- **用户管理**（`User`）：管理员账号的创建、改密、删除。
- **Token 管理**（`Token`）：内部长期凭证的创建、查看、删除。

所有界面只负责与用户的交互，真正的权限判断、Session 校验、Token 校验由后端 `ai-gateway-api` 完成。

## 2. 路由与入口

| 路由 | name | 组件 | 说明 |
|------|------|------|------|
| `/login` | `LoginPassword` | `modules/Login/loginPassword.vue` | 用户名/密码登录页，不渲染主布局。 |
| `/` | `product.home` | `modules/Login/Home.vue` | 登录后首页，展示当前用户欢迎语。 |
| `/user` | `user.list` | `modules/User/index.vue` | 用户与 Token 管理 Tab 页。 |

布局显隐：`layout.vue` 的 `showLayout` 计算属性确保登录页不渲染侧边栏/顶栏，仅当 `route.name` 存在、不是 `LoginPassword`、且用户已登录时才显示完整布局。

## 3. 页面结构

### 3.1 登录页

- 居中登录表单，包含用户名、密码输入框。
- 登录按钮使用 `v-preventReClick` 指令（2 秒防抖），请求期间置为 `loading`。
- 页脚展示前端版本号 `Vue.prototype.Version`。
- 不显示 `layout` 侧边栏与顶部栏。

### 3.2 首页

- 从 `store.getUser()` 读取当前用户，展示欢迎文本 `系统管理员 {user.name}，欢迎！`。
- 无复杂交互，也不直接调用业务接口。

### 3.3 用户列表

- 使用 `pageTable` 展示 `user_name`（可搜索、可排序）、`is_admin`（渲染 `系统管理员`/`普通用户`）、操作列。
- 操作列：修改密码（primary）、删除（error）。
- 顶部「创建用户」按钮打开抽屉。
- Tab 页名称为 `User`（普通用户），通过 `v-if` 惰性渲染。

### 3.4 Token 列表

- 顶部 `Alert` 提示内部用户删除说明。
- 使用 `pageTable` 展示 `name`、`scope`（渲染 `系统`/`支持`）。
- 操作列：详情（primary）、删除（error）。
- 顶部「创建」按钮打开抽屉（width 30）。
- 详情抽屉（width 40）展示 `name`、`scope`、`token` 明文。
- Tab 页名称为 `Token`（内部用户），通过 `v-if` 惰性渲染。

## 5. 前端认证与鉴权流程

### 5.1 登录流程

```
[登录页输入用户名密码]
           ↓
POST /auth/session-keys（withoutAuth: true，不带 Authorization）
           ↓
后端返回 { session_key, user_name, is_admin }
           ↓
store.setUserData(data) → 映射为 { name, sessionKey, is_admin }
           ↓
跳转 product.home
```

`store.setUserData` 将 `{user_name, session_key, is_admin}` 映射为 `{name, sessionKey, is_admin}`，同时写入 `Vue.observable` state 和 `localStorage`。

### 5.2 会话注入

- `utils/request.js` 创建 axios 实例（timeout 30s），请求拦截器为所有业务请求自动注入：
  - `Content-Type: application/json;`
  - `X-Fe-Request-Id: uuidv4()`（每次请求唯一 ID）
  - `Accept-Language: getLang() || 'en'`
  - `Authorization: Session {sessionKey}`（未设 `withoutAuth` 时）
  - URL 拼接前缀：`${protocol}//${host}/open-api/v1/${config.url}`
- 401 响应（非 `withoutAuth` 请求）：清除 `store` 并弹 `$Modal.error`，点确定后跳转登录页。
- 402 响应：**不清除** `removeUserData()`（仅弹框 + 跳转登录），保持本地凭证。
- `withoutAuth` 请求的 401/402：不弹框、不跳转，`isSilent=true` 直接返回，由组件自行处理。
- `unneedTips` 请求：错误时跳过所有 Notice/Modal，`isSilent=true` 直接返回。
- 响应 `data === 'null'` 时替换为 `'{}'`。

### 5.3 路由守卫

- `main.js` 注册 `router.beforeEach`，进入页面前调用 `checkRole(to)`。
- `utils/authorize.js` 首次拉取后端 `meta` 接口（`withoutAuth: true, unneedTips: true`），缓存导航树到 `store`。
- 校验逻辑顺序：
  1. 无 `meta` → 拉取并缓存。
  2. 目标是 `LoginPassword` → 放行。
  3. 无 `userData` → 返回 `'LoginPassword'`（跳转登录）。
  4. `!userData.is_admin` → 返回 `'illegalAccess'`（非管理员禁止访问）。
  5. `excludeRoute`（`product.home`）→ 放行。
  6. `store.findNav(to.name)` 递归搜索 `meta.nav.admin` 树；找不到 → 返回 `'LoginPassword'`。
  7. 找到 → 放行。

> 当前控制台只面向管理员（`is_admin`），普通用户登录后会被视为非法访问。

### 5.4 注销流程

- 顶栏 `headerBar.vue` 用户下拉菜单 → `$Modal.confirm` 确认 → `DELETE /auth/session-keys/{session_key}` → `store.removeUserData()` → 跳转登录页。

### 5.5 权限与 Scope（界面视角）

- 前端本身不保存权限矩阵，只消费后端 `meta` 返回的可见菜单。
- 菜单树与路由 `name` 绑定，点击后通过 `this.$router.push({ name })` 跳转。
- 横向越权由后端 SQL 层通过 `Scope` 过滤，前端无需额外处理。

## 6. 表单字段与校验

### 6.1 登录

| 字段 | 规则 | 说明 |
|------|------|------|
| `user` | 必填（trigger: blur） | 登录用户名。 |
| `password` | 必填（trigger: blur） | 登录密码。 |

> 注：代码中 `formData` 预留了 `code` 字段，但当前未启用验证码流程，模板中未使用。

### 6.2 创建用户

| 字段 | 校验 | 说明 |
|------|------|------|
| `user_name` | `UserNameRegCheck`：1-64 字符；`/^[a-zA-Z0-9]([a-zA-Z0-9._-]{0,62}[a-zA-Z0-9])?$/`；不能以 `.`/`-`/`_` 开头或结尾；无空白；保留名 `admin`/`root`/`system` 不允许 | 用户名格式校验。 |
| `password` | `PasswordRegCheck(value, user_name)`：8-128 字符；无空白；不能等于用户名或用户名反转 | 密码强度校验。 |
| `confirmPass` | 与 `password` 一致 | 二次确认。 |
| `is_admin` | 固定 `true`、disabled | 当前仅支持管理员角色。 |

### 6.3 修改密码

| 字段 | 校验 | 说明 |
|------|------|------|
| `user_name` | required（disabled 输入框） | 由父组件传入。 |
| `old_password` | 仅 `isSelf` 为真时必填（trigger: change） | 仅修改自己密码时需要旧密码。 |
| `new_password` | `PasswordRegCheck(value, user_name)`（trigger: change） | 新密码。 |
| `confirmPass` | 与 `new_password` 一致 | 二次确认。 |

- `isSelf` 判断：`formData.user_name === store.getUser().name`。
- 修改自己密码成功后，前端弹 `$Modal.warning` 提示，点确定后通过 `location.href` 硬跳转到 `/login`（强制重新登录）。
- 修改他人密码：PATCH body 仅含 `{password}`（无需旧密码），成功后仅关闭 Drawer + Message 成功提示，不跳转。

### 6.4 创建 Token

| 字段 | 校验 | 说明 |
|------|------|------|
| `name` | `TokenNameRegCheck`：1-64 字符；`/^[a-zA-Z0-9]([a-zA-Z0-9._-]{0,62}[a-zA-Z0-9])?$/`；保留名 `admin`/`system`/`default` 不允许 | Token 名称。 |
| `scope` | 必填；RadioGroup | `System`（系统）/ `Support`（支持）。 |

> 注：文档前版提及 `Product` scope 和 `product_name` 字段，但当前 UI 仅展示 `System`/`Support` 两个选项，无 `Product` 分支。`CreateToken.vue` 无 props。

## 7. 数据流

```
Login/loginPassword.vue
    → POST /auth/session-keys → store.setUserData → 跳转 product.home

Home.vue
    → store.getUser() → 展示欢迎语

User/index.vue
    ├── User.vue
    │     ├── CreateUser.vue (Drawer) → $emit('submit') → User.vue POST /auth/users
    │     └── UpdatePassword.vue (Drawer) → $emit('submit', data, isSelf) → User.vue PATCH /auth/users/{user_name}/passwd
    └── Token.vue
          ├── CreateToken.vue (Drawer) → $emit('submitData') → Token.vue POST /auth/tokens
          └── 详情 Drawer → Token.vue GET /auth/tokens/{token_name}
```

- 删除当前登录用户时，`User.vue` 对比 `store.getUser().name`，提示后通过 `location.href` 硬跳转到 `/login`。

## 8. OpenAPI 消费映射

| 组件 | 方法 | 相对 URL | 说明 |
|------|------|----------|------|
| `loginPassword.vue` | `POST` | `auth/session-keys` | 创建会话，`withoutAuth: true`。 |
| `authorize.js` | `GET` | `meta` | 导航与权限元数据，`withoutAuth: true, unneedTips: true`。 |
| `headerBar.vue` | `DELETE` | `auth/session-keys/{session_key}` | 注销会话。 |
| `User.vue` | `GET` | `auth/users` | 用户列表。 |
| `User.vue` | `POST` | `auth/users` | 创建用户。 |
| `User.vue` | `PATCH` | `auth/users/{user_name}/passwd` | 修改密码。自我修改 body=`{old_password, password}`，他人修改 body=`{password}`。 |
| `User.vue` | `DELETE` | `auth/users/{user_name}` | 删除用户。 |
| `Token.vue` | `GET` | `auth/tokens` | Token 列表。 |
| `Token.vue` | `GET` | `auth/tokens/{token_name}` | Token 详情。 |
| `Token.vue` | `POST` | `auth/tokens` | 创建 Token。 |
| `Token.vue` | `DELETE` | `auth/tokens/{token_name}` | 删除 Token。 |

> 注：实际代码使用 `PATCH` 修改密码，与 `OpenAPI消费接口映射.md` 中标注的 `PUT` 不一致，以代码实现为准。文档前版标注的 `CreateToken.vue GET products` 不存在，当前代码无此调用。

## 9. 边界情况

- 登录失败：解析后端 `ErrMsg`（按 `:` 分割取后半段），无具体内容时展示通用失败提示。
- 401 响应（非 `withoutAuth`）：全局拦截器 `store.removeUserData()` 清除用户数据并跳转登录页。
- 402 响应：不清除本地凭证，仅弹框 + 跳转。
- 修改当前登录用户密码：成功后弹 `$Modal.warning` 提示，点确定后 `location.href` 硬跳转到 `/login`。
- 删除当前登录用户：成功后弹 `$Modal.error`，点确定后 `location.href` 硬跳转到 `/login`。
- Token 详情抽屉展示明文 Token，关闭后不再保留敏感数据。
- `UserNameRegCheck` 保留名：`admin`/`root`/`system`；`TokenNameRegCheck` 保留名：`admin`/`system`/`default`（略有差异）。
- 密码不能等于用户名或用户名反转（`PasswordRegCheck` 接受 `userName` 参数）。
- 当前控制台只支持管理员角色，后续若开放普通用户，需调整 `is_admin` 校验与菜单过滤逻辑。
