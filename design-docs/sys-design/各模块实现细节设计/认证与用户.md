# 认证与用户模块细节设计

## 1. 模块定位

本模块覆盖前端所有与**身份认证**和**用户/Token 管理**相关的界面：

- **登录**（`Login`）：管理员入口，获取并保存会话。
- **首页**（`Home`）：登录后欢迎页，展示当前用户。
- **用户管理**（`User`）：管理员账号的创建、改密、删除。
- **Token 管理**（`Token`）：内部长期凭证的创建、查看、删除。

所有界面只负责与用户的交互，真正的权限判断、Session 校验、Token 校验由后端 `ai-gateway-api` 完成。

## 2. 路由与入口

| 路由 | name | 组件 | 说明 |
|------|------|------|------|
| `/login` | `LoginPassword` | `modules/Login/loginPassword.vue` | 用户名/密码登录页，不渲染主布局。 |
| `/` | `product.home` | `modules/Login/Home.vue` | 登录后首页，展示当前用户欢迎语。 |
| `/user` | `user.list` | `modules/User/index.vue` | 用户与 Token 管理 Tab 页。 |

## 3. 页面结构

### 3.1 登录页

- 居中登录表单，包含用户名、密码输入框。
- 登录按钮在请求期间置为 `loading`。
- 页脚展示前端版本号 `Vue.prototype.Version`。
- 不显示 `layout` 侧边栏与顶部栏。

### 3.2 首页

- 从 `store` 读取当前用户，仅展示欢迎文本。
- 无复杂交互，也不直接调用业务接口。

### 3.3 用户列表

- 使用 `pageTable` 展示 `user_name`、`is_admin` 等字段。
- `user_name` 列支持搜索与排序。
- 操作列：修改密码、删除。
- 顶部「创建用户」按钮打开抽屉。

### 3.4 Token 列表

- 使用 `pageTable` 展示 `name`、`scope`。
- `scope` 列渲染为 `System` / `Support` 文案。
- 操作列：详情、删除。
- 顶部「创建」按钮打开抽屉。
- 删除前展示 Alert 说明。

## 5. 前端认证与鉴权流程

### 5.1 登录流程

```
[登录页输入用户名密码]
           ↓
POST /auth/session-keys（withoutAuth: true）
           ↓
后端返回 { sessionKey, user }
           ↓
this.$store.setUserData(data)
           ↓
跳转 product.home
```

### 5.2 会话注入

- `utils/request.js` 为所有业务请求自动注入 `Authorization: Session <sessionKey>`。
- 401 响应：全局拦截器清除 `store` 并跳转登录页。
- 402 响应：保持登录态，提示无权限。

### 5.3 路由守卫

- `main.js` 注册 `router.beforeEach`，进入页面前调用 `checkRole(to)`。
- `utils/authorize.js` 首次拉取后端 `meta` 接口，缓存导航树到 `store`。
- 校验逻辑：未登录、非管理员、目标路由不在导航树中，均跳转登录。

> 当前控制台只面向管理员（`is_admin`），普通用户登录后会被视为非法访问。

### 5.4 权限与 Scope（界面视角）

- 前端本身不保存权限矩阵，只消费后端 `meta` 返回的可见菜单。
- 菜单树与路由 `name` 绑定，点击后通过 `this.$router.push({ name })` 跳转。
- 横向越权由后端 SQL 层通过 `Scope` 过滤，前端无需额外处理。

## 6. 表单字段与校验

### 6.1 登录

| 字段 | 规则 | 说明 |
|------|------|------|
| `user_name` | 必填 | 登录用户名。 |
| `password` | 必填 | 登录密码。 |

> 注：代码中预留了 `formData.code` 字段，但当前未启用验证码流程。

### 6.2 创建用户

| 字段 | 校验 | 说明 |
|------|------|------|
| `user_name` | `UserNameRegCheck` | 用户名格式校验。 |
| `password` | `PasswordRegCheck` | 密码强度校验。 |
| `confirmPass` | 与 `password` 一致 | 二次确认。 |
| `is_admin` | 固定 `true`、disabled | 当前仅支持管理员角色。 |

### 6.3 修改密码

| 字段 | 校验 | 说明 |
|------|------|------|
| `old_password` | 必填 | 仅修改自己密码时必填。 |
| `new_password` | `PasswordRegCheck` | 新密码。 |
| `confirmPass` | 与 `new_password` 一致 | 二次确认。 |

- 修改自己密码成功后，前端会清除会话并跳转登录页。

### 6.4 创建 Token

| 字段 | 校验 | 说明 |
|------|------|------|
| `name` | 必填 | Token 名称。 |
| `scope` | 必填 | `System` / `Support`；代码预留 `Product` 分支但 UI 未展示。 |
| `product_name` | `scope === 'Product'` 时必填 | 产品线关联。 |

## 7. 数据流

```
Login/loginPassword.vue
    → POST /auth/session-keys → store.setUserData → 跳转 product.home

Home.vue
    → store.getUser() → 展示欢迎语

User/index.vue
    ├── User.vue
    │     ├── CreateUser.vue (Drawer) → $emit('submit') → User.vue POST/DELETE
    │     └── UpdatePassword.vue (Drawer) → $emit('submit') → User.vue PATCH
    └── Token.vue
          ├── CreateToken.vue (Drawer) → $emit('submitData') → Token.vue POST
          └── 详情 Drawer → Token.vue GET /auth/tokens/{token_name}
```

- 删除当前登录用户时，`User.vue` 对比 `this.$store.getUser().name`，提示后跳转登录。

## 8. OpenAPI 消费映射

| 组件 | 方法 | 相对 URL | 说明 |
|------|------|----------|------|
| `loginPassword.vue` | `POST` | `auth/session-keys` | 创建会话，`withoutAuth: true`。 |
| `User.vue` | `GET` | `auth/users` | 用户列表。 |
| `User.vue` | `POST` | `auth/users` | 创建用户。 |
| `User.vue` | `PATCH` | `auth/users/{user_name}/passwd` | 修改密码。 |
| `User.vue` | `DELETE` | `auth/users/{user_name}` | 删除用户。 |
| `Token.vue` | `GET` | `auth/tokens` | Token 列表。 |
| `Token.vue` | `GET` | `auth/tokens/{token_name}` | Token 详情。 |
| `Token.vue` | `POST` | `auth/tokens` | 创建 Token。 |
| `Token.vue` | `DELETE` | `auth/tokens/{token_name}` | 删除 Token。 |
| `CreateToken.vue` | `GET` | `products` | 产品线列表。 |
| `authorize.js` | `GET` | `meta` | 导航与权限元数据。 |

> 注：实际代码使用 `PATCH` 修改密码，与 `OpenAPI消费接口映射.md` 中标注的 `PUT` 不一致，以代码实现为准。

## 9. 边界情况

- 登录失败：解析后端 `ErrMsg`，无具体内容时展示通用失败提示。
- 401 响应：全局拦截器清除 `store` 并跳转登录页。
- 修改当前登录用户密码：成功后弹窗提示并重新登录。
- 删除当前登录用户：确认后跳转登录页。
- Token 详情抽屉展示明文 Token，关闭后不再保留敏感数据。
- 当前控制台只支持管理员角色，后续若开放普通用户，需调整 `is_admin` 校验与菜单过滤逻辑。
