# AI Gateway Web 模块设计文档

## 1. 设计目标

业务模块是 `ai-gateway-web` 的核心组织单元。本文档定义：

- 模块的划分原则与目录结构。
- 每个模块的职责边界。
- 模块内部统一的页面与组件模式。
- 模块间通信与数据隔离规则。

## 2. 模块划分原则

模块按 **AI 网关的管理领域** 进行划分，每个模块对应一个独立的功能域：

| 原则 | 说明 |
|------|------|
| 按业务领域 | 每个模块对应一个可独立理解的管理对象（如 Cluster、Route、API Key）。 |
| 高内聚 | 模块内部的页面、组件、工具函数应围绕同一业务对象组织。 |
| 低耦合 | 模块之间不直接引用内部组件，共享能力通过 `src/components/` 和 `src/utils/` 提供。 |
| 页面结构一致 | 每个模块采用统一的“列表页 + 抽屉/弹窗 + 子表单”模式。 |

## 3. 模块目录结构

每个模块位于 `src/modules/<ModuleName>/`，内部结构如下：

```
src/modules/<ModuleName>/
├── index.vue              # 列表页：表格、搜索、操作入口
└── components/            # 模块私有组件
    ├── index.vue          # 新建/编辑向导容器（可选）
    ├── Upsert.vue         # 编辑/新建弹窗（可选）
    ├── Review.vue         # 详情/复核展示（可选）
    ├── *.vue              # 子表单或子步骤组件
```

## 4. 模块职责总览

| 模块 | 路径 | 核心职责 | 路由 name |
|------|------|----------|-----------|
| 登录 | `modules/Login` | 登录页、首页入口。 | `LoginPassword`、`product.home` |
| 用户 | `modules/User` | 用户管理、Token 管理、密码修改。 | `user.list` |
| AI 实例池 | `modules/AIInstancePool` | AI 网关实例池列表与管理。 | `AIGatewayInstancePool.list` |
| AI 业务集群 | `modules/Clusters` | Cluster 的新建/编辑/详情，包含多步骤向导与 LLM 配置。 | `AICluster.list` |
| 模型定价 | `modules/ModelPrices` | 模型价格列表、创建/编辑、YAML 导入。 | `ModelPrice.list` |
| 路由表 | `modules/RouteTable` | Global / Entity / API-Key 三级路由表与规则（`targets` / `fallbacks`）。 | `AdvanceRouteRule.list` |
| API Key | `modules/APIKey` | API Key 的创建、查看、重置配额。 | `APIKey.list` |
| Entity | `modules/Entity` | Entity（服务实体）与 Entity Type 管理。 | `Entity.list` |
| 证书 | `modules/Cert` | 证书上传与管理（当前路由已注释）。 | `certs.list`（未启用） |

## 5. 统一页面模式

### 5.1 列表页

`index.vue` 作为模块入口，职责：

- 渲染 `pageTable` 表格，展示后端数据。
- 提供“新建”按钮。
- 处理行级操作：编辑、详情、删除。
- 通过 `Drawer` 或 `Modal` 打开编辑/详情组件。
- 管理 `loading` 状态与表格数据。

典型生命周期：

```
mounted → getData() → this.$request → tableData → pageTable 渲染
```

### 5.2 编辑/新建向导

复杂对象（如 Cluster）使用多步骤向导容器：

- `components/index.vue` 作为向导容器，使用 `Steps` 组件串联多个子表单。
- 子表单组件如 `BaseConfig`、`Timeout`、`InstancePool`、`GatewayConfig`、`PassiveHealthCheck` 等。
- 每个子表单通过 `props` 接收初始数据，通过 `$emit('submitData')` 提交本步骤数据。
- 父容器合并所有步骤数据，最后一步 `Review` 聚合展示并提交到后端。

### 5.3 详情/复核

- `Review.vue` 只读展示对象完整数据。
- 既作为向导最后一步使用，也作为列表页“详情”抽屉使用。
- 通过 `props` 接收分解后的数据对象，避免直接引用原始响应结构。

### 5.4 弹窗组件

- 简单对象（如 API Key、Entity）使用 `Upsert.vue` 或 `Create.vue` 弹窗。
- 弹窗内部完成表单校验与提交，成功后 `$emit` 通知列表页刷新。

## 6. 模块内部组件规范

### 6.1 组件分类

| 类型 | 命名示例 | 职责 |
|------|----------|------|
| 列表容器 | `index.vue` | 拉取数据、打开抽屉/弹窗。 |
| 向导容器 | `components/index.vue` | 多步骤表单容器，协调子表单。 |
| 子表单 | `BaseConfig.vue` | 负责对象的一部分字段。 |
| 详情展示 | `Review.vue` | 只读聚合展示。 |
| 操作弹窗 | `Upsert.vue`、`Create.vue` | 单表单新建/编辑。 |
| 视图组件 | `ApiKeyView.vue`、`EntityView.vue` | 详情查看与配额操作。 |

### 6.2 数据流

- 列表页 → 容器组件：通过 `props` 传入当前行数据、模式标志。
- 容器组件 → 子表单：通过 `props` 下发分片数据与 `reportFlag`。
- 子表单 → 容器组件：通过 `$emit('submitData', { topic, data })` 提交。
- 容器组件 → 列表页：通过 `$emit('submit')` 通知刷新。

## 7. 模块间交互规则

1. **禁止直接引用其他模块内部组件**：如需共享，应提取到 `src/components/` 或 `src/utils/`。
2. **共享状态通过 `store.js`**：如用户会话、导航元数据。
3. **后端接口前缀统一**：所有模块通过 `this.$request` 访问 `/open-api/v1/*`。
4. **模块自治**：每个模块独立完成列表、增删改查、详情查看。

## 8. 扩展新模块 checklist

新增业务模块时，按以下步骤执行：

- [ ] 在 `src/modules/` 下创建 `<ModuleName>/` 目录。
- [ ] 实现 `index.vue` 列表页，使用 `pageTable` 组件。
- [ ] 在 `src/router/router.js` 中注册路由，使用 `require.ensure` 代码分割。
- [ ] 在 `src/i18n/en.js` 与 `src/i18n/zh.js` 中补充语言包。
- [ ] 在 `src/utils/authorize.js` 的导航树中（由后端 `meta` 接口控制）确认可见性。
- [ ] 更新本文档与 `OpenAPI消费接口映射.md`，补充接口映射。
- [ ] 若涉及通用组件变化，同步更新 `组件与复用设计文档.md`。
