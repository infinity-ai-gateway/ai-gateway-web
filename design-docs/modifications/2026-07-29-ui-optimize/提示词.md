# UI 改动 AI 协作提示词记录

## 一、背景与目标

本次改造对 `ai-gateway-web` 的 OpenAPI 调用与产品原型进行对齐，最终形成一套与前端代码实现一致的 UI 代码变更文档及源码实现。

文档版本管理策略：后续设计文档本身不再维护独立的版本号，版本信息统一跟随 Git 版本号管理。

## 二、改造范围

- `design-docs/modifications/2026-07-29-open-api-optimize/`：UI 变更分析与方案文档
- `design-docs/api-define/`：OpenAPI 接口定义文档
- `design-docs/prototype-design/`：原型 HTML/JS 文件
- `ai-gateway-web/src/` 源码
- `gui-test-for-ai-gateway/docs/`：GUI 功能测试文档

## 三、关键原则

1. **以差异分析为准**：先生成 `ui-code-changes.md` 明确当前 UI 与目标原型、目标接口定义的差距。
2. **以代码实现为最终依据**：UI 文档和源码修改需与实际运行效果保持一致。
3. **不直接参考目标版本草稿**：`prototype-design/` 原型文件仅用于差异对比，不作为直接修改 `src/` 代码的依据。
4. **文档去版本号**：从 `design-docs` 相关文档中删除独立的版本号及版本历史信息。
5. **测试同步更新**：GUI 测试用例、测试场景随接口与交互变更同步刷新。

## 四、分阶段提示词

**目标**：生成 `ui-code-changes.md`，列出当前 UI 与目标原型、目标接口之间的差异。

- 原型与 UI 差异：`design-docs/modifications/2026-07-29-open-api-optimize/prototype-ui-compare.md`

### 阶段 2：Review 并修正 ui-code-changes.md

## 五、关键决策记录

| 决策点 | 结论 |
|--------|------|
| 路由管理模块 | 新增 `RouteTable` 模块，删除旧 `Routes/` 和 `AIRouteRules/` |
| 路由规则详情组件 | 拆分为 `RouteRules.vue`（容器）、`RuleView.vue`（只读）、`RuleForm.vue`（编辑） |
| 详情页返回方式 | 没有独立「返回」按钮，依赖全局面包屑返回 |
| 查看模式规则展示 | 使用 `RuleView.vue`，不使用 `RuleForm.vue` 的 `readonly` 模式 |
| 导航菜单 | 统一为「路由管理 → 路由表」，路由 `name` 为 `AdvanceRouteRule.list` |
| APIKey 模型数据源 | 从 `/global-models` 改为 `/clusters` |
| Entity 模型数据源 | 从 `/global-models` 改为 `/clusters` |
| Cluster 模型提供商 | 从 `/model-providers` 改为 `/model-provider-types` |
| Cluster 获取模型 | 从 `/models` 改为 `/tools/get-models-from-provider` |
| 路由表启用/停用 | 先 GET 完整规则再 PUT/PATCH，避免覆盖清空 |

## 六、最终成果

- `ui-code-changes.md`：准确的 UI 代码变更分析
- `ai-gateway-web/src/` 源码：实现新的路由管理、模型数据源、接口路径调整
- `gui-test-for-ai-gateway/docs/`：更新后的 GUI 功能测试文档

本文档记录的是与 AI 协作完成本次 UI 改造时使用的提示词与关键决策。实际执行过程中，针对各阶段的输出均进行了人工 review 与代码求证，确保最终文档、代码、测试三者一致。
