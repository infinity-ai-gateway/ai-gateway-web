# 07 消费者管理：API Key

API Key 是最终下发给调用方的凭证，请求时携带。API Key 可挂载到某个 Entity 组织，继承其治理策略（配额、限流、模型访问控制），也可独立配置自身策略。

消费者管理 → API Key 管理。

## 7.1 Key 列表

![API-Key列表](images/05-apikey-list.png)

**表格列说明**：

| 列名 | 说明 |
| --- | --- |
| Key ID | Key 唯一标识，支持搜索 |
| Key 值 | 脱敏显示（前 8 位 + `****` + 后 4 位），可点击查看完整值 |
| 描述 | Key 用途说明，支持搜索 |
| 状态 | 启用 / 停用，支持下拉筛选 |
| 配额类型 | 无限 / 有限，支持下拉筛选 |
| 配额 | 有限配额时显示 `已用 / 总量`，无限配额时显示 `-` |
| 限流状态 | 已启用 / 未启用，支持下拉筛选 |
| 挂载Entity | 挂载的组织名称，未挂载显示 `-` |
| 操作 | 管理路由规则、编辑、删除 |

点击列表中任意一行可查看 Key 详情。列表上方有「创建」按钮（右上角）。

### 查看 Key 值

点击列表中的 Key 值，弹出详情弹窗，展示完整 Key 明文值，旁边有复制图标可一键复制到剪贴板。

> Key 值创建后不可修改，请妥善保存。

### 查看详情

点击 Key 行，右侧弹出详情抽屉，以只读方式展示 Key 全部配置：

![Key详情](images/05-apikey-detail.png)

- **基本信息**：描述、Key ID、Key 值（可复制）、状态、过期时间、执行配额检查、允许模型、允许子网、挂载Entity、创建时间、更新时间
- **配额信息**：配额类型（无限/有限）、配额总量、已使用（含百分比）、剩余量、使用进度条、重置周期。有限配额时可点击「重置配额」按钮重置。
- **限流配置**：限流状态、最大并发、TPM 规则列表、RPM 规则列表

## 7.2 创建 Key

点击列表上方的「创建」按钮，右侧弹出创建抽屉。表单分为三个区域：基本信息、配额信息、限流配置。

![创建API-Key](images/05-apikey-create.png)

### 基本信息

| 字段 | 必填 | 默认值 | 格式要求 | 说明 |
| --- | --- | --- | --- | --- |
| 描述 | 是 | 空 | 最多 512 字符 | Key 用途说明 |
| 过期时间 | 是 | 永不过期 | 勾选「永不过期」则无需选择日期；不勾选时需选择日期（不可选择今天之前） | 凭证有效期 |
| 启用状态 | 否 | 启用 | 启用 / 停用 | Key 是否可用 |
| 执行配额检查 | 否 | 是 | 是 / 否 | 选「是」时，请求参与配额扣减（配合「有限配额」生效）；选「否」时不执行配额检查，即使配置了有限配额也不会因配额不足拒绝请求，适合调试阶段 |
| 允许模型 | 否 | `*`（全部模型） | — | Key 自身的模型访问控制。选 `*` 表示**允许所有模型**（最宽松）；选具体模型表示**只允许这些模型**（更严格）。二者只能二选一：选了 `*` 就不能再选具体模型；选了具体模型，`*` 自动取消 |
| 允许子网 | 否 | `*`（不限制） | CIDR 格式，每行一个；`*` 与其他网段不可混用 | 允许访问的客户端 IP 网段 |
| 挂载Entity | 否 | 空 | — | 关联到某个组织，挂载后同时受该组织及全部祖先组织的策略约束 |

> **常见示例**：
>
> | 场景 | 填写内容 |
> | ------ | -------- |
> | 不限制 IP（默认） | `*` |
> | 只允许本公司内网 | `10.0.0.0/8` |
> | 只允许某个办公室 | `192.168.1.0/24` |
> | 只允许特定服务器 | `172.16.5.10/32` |
>
> `/8`、`/24`、`/32` 是子网掩码简写，表示允许的 IP 范围大小。不确定时询问你的网络管理员。

### 配额信息

| 字段 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 无限配额 | — | 是 | 选「否」后展开以下字段 |
| 配额不足时放行 | 否 | 否 | 选"是"时，即使配额用完，请求仍然会被放行（不会被拒绝），但系统会继续统计用量。适合"先观察实际消耗、暂不拦截"的试运行阶段。选"否"时，配额用完则直接拒绝请求（返回配额不足错误） |
| 配额总量 | 是 | `100000000` | 非负整数，周期内可用 Token 总量 |
| 配额单位 | — | `total_token` | 固定为 total_token |
| 重置周期 | — | 永不重置 | 永不重置 / 每周 / 每月 |

### 限流配置

| 字段 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 启用限流 | — | 否 | 选「是」后展开以下规则区域 |

启用限流后，可配置 TPM 规则、RPM 规则和最大并发，需至少配置一项有效规则。

| 类型 | 适用场景 |
| ------ | ---------- |
| TPM | 控制 Token 消耗（长文本、推理成本高的场景） |
| RPM | 控制请求次数（防刷接口、限制 QPS） |
| 最大并发 | 控制同时处理的请求数（防止压垮后端） |

#### TPM 规则

**TPM（每分钟 Token 数）限流**：采用滑动窗口机制，平滑统计一段时间内的 Token 用量。每项最多 3 条规则。

**通俗理解**：

- **时间窗口**：你看多久范围内的用量。比如窗口 10 分钟，就是看过去 10 分钟用了多少 Token。
- **滑动步长**：统计窗口多久向前"滑"一次。比如步长 1 分钟，就是每分钟重新计算一次过去 10 分钟的总量。
- **最大 Token 数**：这个时间窗口内允许的 Token 上限。超过就限流（返回 429）。

**举例**：时间窗口 = 10 分钟，滑动步长 = 1 分钟，最大 Token 数 = 10000。表示"检查过去 10 分钟内的 Token 用量，每 1 分钟检查一次，超过 10000 就拒绝"。

> **建议**：如无特殊需求，保持默认值即可（窗口 1 分钟，步长 1 分钟）。

| 字段 | 必填 | 默认值 | 格式要求 | 说明 |
| --- | --- | --- | --- | --- |
| 规则名称 | 是 | 空 | 1-128 字符；同类型内不能重复 | 规则标识 |
| 适用模型 | 是 | `*`（全部模型） | — | `*` 或指定模型 |
| 时间窗口(分) | 是 | `1` | 1-360 的整数 | 统计的时间范围 |
| 最大Token数 | 是 | `10000` | 非负整数 | 窗口内允许的最大 Token 数 |
| 滑动步长(分) | 是 | `1` | 1-360 的整数；不超过时间窗口 | 滑动窗口的步长 |

#### RPM 规则

RPM（Request Per Minute）采用**固定窗口**机制，以时间窗口为周期计数。每项最多 3 条规则。

| 字段 | 必填 | 默认值 | 格式要求 | 说明 |
| --- | --- | --- | --- | --- |
| 规则名称 | 是 | 空 | 1-128 字符；同类型内不能重复 | 规则标识 |
| 适用模型 | 是 | `*`（全部模型） | — | `*` 或指定模型 |
| 时间窗口(分) | 是 | `1` | 1-360 的整数 | 统计的时间范围 |
| 最大请求数 | 是 | `100` | 非负整数 | 窗口内允许的最大请求数 |

> 注意：RPM 规则没有滑动步长字段，与 TPM 的区别在此。

#### 最大并发

| 模式 | 说明 |
| --- | --- |
| 不限制 | 不限制并发数（值为 -1），单独使用不会触发限流 |
| 封禁 | 禁止所有并发请求（值为 0） |
| 限制并发数 | 限制最大并发数，需填写具体数值（正整数） |

> **说明**：最大并发是"辅助选项"。
>
> - 如果你想**只做请求速率控制**（如每分钟 100 次），选"不限制"并发，只配 RPM 规则即可。
> - 如果你想**同时控制并发数**（如最多 10 个请求同时处理），选"限制并发数"并配合 TPM/RPM 使用。
> - "封禁"（0）是一个快捷选项，用于紧急停止所有请求。
>
> 因此"不限制"不是"无效"，而是表示"不限并发，让 TPM/RPM 单独发挥作用"。

### 提交创建

点击底部「提交」按钮提交表单。创建成功后关闭抽屉，提示「创建成功!」，列表自动刷新。

> Key 值由系统自动生成。创建成功后：
>
> 1. 在列表中找到你刚创建的 Key 那一行
> 2. 点击那一串像 `sk-abc****def` 的**Key 值文本**
> 3. 在弹出的详情框中点击**复制图标**，保存好这个完整字符串
>
> > 之后仍可在列表中再次点击查看，但建议创建当下就保存到安全位置，避免遗忘或误删。

## 7.3 编辑 Key

点击操作列的「编辑」按钮，右侧弹出编辑抽屉。所有字段均可编辑，字段预填充当前值。

编辑模式下，服务鉴权 Key 等已配置的字段会显示提示「已配置 Key，如需修改请输入新 Key；留空则保持不变」。

## 7.4 删除 Key

点击操作列的「删除」按钮，弹出确认框「是否删除API Key 管理 {描述}？」。确认后立即删除，提示「删除成功!」，列表自动刷新。

> 注意：删除 Key 会级联清理其专属配额与限流策略，且可能影响在途请求，请谨慎操作。

## 7.5 重置配额

![重置配额](images/05-apikey-reset-quota.png)

在 Key 详情抽屉的配额信息区域，有限配额时显示「重置配额」按钮。点击后弹出重置弹窗：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 新的配额总量 | 是 | 非负整数，可设置新的配额总量 |
| 重置原因 | 否 | 选填，记录重置原因 |

> 重置后已使用量归零，配额总量更新为新设置的值。

## 7.6 管理路由规则

点击操作列的「管理路由规则」按钮，跳转到路由规则页面，自动筛选出属主为该 Key 的路由规则。详见 [08 章](08-route.md)。

> Key 创建后会自动生成属主为该 Key 的 apikey 路由表。

## 7.7 运行时生效机制

API Key 的运行时检查与 Entity 组织一致，按固定顺序执行：**模型访问控制 → 限流检查 → 配额扣减**，任一环节失败立即拒绝。

- **模型访问控制**：先检查 Key 自身的允许模型，再遍历挂载组织及全部祖先的允许/禁止模型列表。
- **限流检查**：收集 Key 自身 + 挂载组织 + 全部祖先的限流策略，全部通过才放行。
- **配额扣减**：收集 Key 自身 + 组织链上所有有限配额的计划，逐一扣减。

> 路由表优先级 API-Key > Entity > Global。

## 7.8 注意事项

- Key 值创建后不可修改，请创建成功后立即妥善保存。
- Key 可独立配置配额和限流，也可挂载到 Entity 组织继承其策略。
- 删除 Key 会级联清理其专属配额与限流策略。
- 挂载到组织后，Key 同时受该组织及全部祖先组织的策略约束。
- 修改 Key 策略实时生效，请在低峰期操作。
