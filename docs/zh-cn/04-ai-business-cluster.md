# 04 资源管理：AI 业务集群

业务集群是**后端模型服务**在网关内的抽象，也是流量转发的承载者：一个集群 = 一组后端实例（IP 或服务商域名）+ 协议 / 会话保持 / 超时重试 / 被动健康检查 / 模型配置。路由规则的目标即为「集群 + 模型」，请求被转发到集群内的后端实例。

## 首次接入最小配置

首次创建集群时，只需关注以下必填项，其余步骤保持默认即可：

| 向导步骤 | 必填项 |
| ------ | ------ |
| 1 基础配置 | 集群名称、协议（http / https 与后端一致） |
| 4 实例配置 | IP 或服务商域名 + 端口 + 权重（单实例填 100） |
| 5 大模型配置 | 模型服务商、点「获取」选择模型 |
| 2 / 3 / 6 | 保持默认，直接下一步 |

## 4.1 集群列表

进入 资源管理 → AI 业务集群，展示当前已创建的集群列表。

![集群列表](images/04-cluster-list.png)

**表格列说明**：

| 列名 | 说明 |
| --- | --- |
| 名称 | 集群名称，支持按名称搜索和排序 |
| 描述 | 集群说明 |
| 操作 | 详情、编辑、删除 |

列表上方有「添加集群」按钮（右上角）。

### 查看详情

点击操作列的「详情」按钮，右侧弹出详情抽屉，以只读方式展示集群全部配置（基础配置、超时和重传、被动健康检查、实例配置、大模型配置），与 [3.8 复查&检查](#38-步骤-6复查检查) 的汇总面板一致。

### 删除集群

点击操作列的「删除」按钮，弹出确认框「确认删除 {集群名称}?」。

- **正常删除**：确认后立即删除，提示「删除成功!」，列表自动刷新。
- **被路由规则引用时**：弹出删除失败弹窗，提示「集群 {集群名称} 被路由表 {路由表}（路由表类型/路由表属主）的 {规则} 路由规则引用，无法删除。可以点击链接前往对应路由表快速处理：」，并提供「前往处理」链接跳转到对应路由表。需先在路由表中解除引用后才能删除。

## 4.2 创建 / 编辑集群

点击列表上方的「添加集群」按钮，右侧弹出创建抽屉，采用 **6 步向导**：

1. 基础配置 → 2. 超时和重传 → 3. 被动健康检查 → 4. 实例配置 → 5. 大模型配置 → 6. 复查&检查

编辑已有集群时，同样的抽屉以编辑模式打开，字段预填充。

> 注意：集群名称创建后不可修改，编辑模式下该字段为灰色禁用状态。

## 4.3 步骤 1：基础配置

![基础配置](images/04-cluster-wizard-base.png)

**表单字段**：

| 字段 | 必填 | 默认值 | 校验规则 | 说明 |
| --- | --- | --- | --- | --- |
| 集群名称 | 是 | 空 | 1-64 字符；仅允许字母、数字、点(`.`)、下划线(`_`)、中划线(`-`)；不能以点、下划线、中划线开头或结尾；不能与已有集群重名 | 唯一标识，创建后不可修改 |
| 集群说明 | 否 | 空 | 不能超过 256 个字符；不能包含控制字符 | 描述用途 |
| 协议 | 是 | `https` | — | http / https，按后端实际选择 |
| 单个后端最大空闲连接数 | 否 | `0` | 非负整数；不超过 99999999 | 转发引擎为每个后端实例维持的空闲长连接数；0 表示无需特别维持，设为非 0 可提升转发性能 |
| 会话保持 | 否 | 停用 | — | 启用 / 停用，见下方说明 |
| 哈希策略 | 条件必填 | `CLIENT_IP_ONLY` | — | 会话保持启用时显示 |
| 哈希头部 | 条件必填 | 空 | 会话保持启用且策略为 CLIENT_ID_ONLY 或 CLIENT_ID_PREFERED 时必填 | Header 名称或 `Cookie:{key}` |
| 请求写缓存大小（Byte） | 否 | `512` | 正整数；不超过 99999999 | 转发引擎向后端写入请求时的缓存大小，一般保持默认 |
| 后端连接随客户端连接关闭 | 否 | 停用 | — | 启用后客户端关闭连接时引擎同时关闭对应的后端连接；停用时按默认策略关闭 |

**会话保持与哈希策略**：

先将会话保持设为「启用」，才会出现「哈希策略」下拉框：

![哈希策略选项](images/04-cluster-hash-options.png)

| 策略 | 含义 | 哈希头部 |
| --- | --- | --- |
| CLIENT_IP_ONLY | 仅根据客户端 IP 做会话保持（默认值）；客户端无稳定标识、只能依赖来源 IP 时使用 | 不需要 |
| CLIENT_ID_ONLY | 仅根据请求中的哈希头部做会话保持；请求稳定携带用户标识 Header / Cookie 时使用 | 必填 |
| CLIENT_ID_PREFERED | 优先使用哈希头部；请求无该头部时回退到客户端 IP | 必填 |

选择 CLIENT_ID_ONLY / CLIENT_ID_PREFERED 后，会出现「哈希头部」输入框，需填写请求中用于会话保持的 Header 名称（如 `x-client-id`）；若使用 Cookie 作为哈希 key，格式为 `Cookie:${key}`（如 `Cookie:USERID`）：

![哈希头部](images/04-cluster-hash-header.png)

> 建议：业务请求能稳定携带用户标识 Header 时选 CLIENT_ID_PREFERED 并填写头部名；只能依赖来源 IP 时选 CLIENT_IP_ONLY。

## 4.4 步骤 2：超时和重传

![超时和重传](images/04-cluster-wizard-timeout.png)

**表单字段**：

| 字段 | 默认值(ms) | 校验规则 | 说明 |
| --- | --- | --- | --- |
| 客户端连接空闲超时 | `30000` | 正整数；不超过 99999999 | 上一个请求结束到读完下一个请求头部的超时，长连接空闲回收 |
| 读客户端请求Body超时 | `30000` | 正整数；不超过 99999999 | 从读到请求 header 开始，直到整个请求应答结束（读 body + 等待后端响应 + 写响应）的超时；客户端或后端处理过慢时触发 |
| 连接后端超时 | `50000` | 正整数；不超过 99999999 | 发起到后端建连至建连完成的超时 |
| 读后端响应头部超时 | `50000` | 正整数；不超过 99999999 | 开始向后端发请求到收完响应头部的超时，首包超时，流式场景关键 |
| 写响应超时 | `60000` | 正整数；不超过 99999999 | 开始向客户端写响应到写完全的超时，客户端接收过慢时断开 |
| 集群内重试次数 | `2` | 非负整数；不超过 99999999 | 转发失败后同集群内重试次数 |

> 大模型推理首包耗时较长，「读后端响应头部超时」建议按服务商 SLA 放宽，避免正常请求被误超时。

## 4.5 步骤 3：被动健康检查

连续转发失败超过「故障阈值」时，实例被置为不健康并启动健康检查，间隔「健康检查间隔」探测恢复。

![被动健康检查](images/04-cluster-wizard-healthcheck.png)

**表单字段**：

| 字段 | 必填 | 默认值 | 校验规则 | 说明 |
| --- | --- | --- | --- | --- |
| 故障阈值 | 否 | `3` | 非负整数；不超过 99999999 | 连续转发失败超过该阈值时，实例被置为不健康并启动健康检查 |
| 健康检查间隔(ms) | 否 | `1000` | 非负整数；不超过 99999999 | 启动健康检查后，检查请求的时间间隔 |
| 健康检查Host | 否 | 空 | 合法域名或 IP 格式 | 检查请求的 Host 字段。留空时使用实例池首个实例的地址 |
| 健康检查Uri | 否 | `/` | 必须以 `/` 开头 | 检查请求的绝对路径 |
| 健康检查期望的状态码 | 否 | `0` | 0 或 100-599 之间的整数 | 判定健康的状态码；填 0 表示忽略状态码，只要有响应即视为健康 |

## 4.6 步骤 4：实例配置

实例形态支持两种，二选一：

![实例配置](images/04-cluster-wizard-instance.png)

### IP 模式（默认）

自建机房 / 私有化部署的后端实例（vLLM / Xinference / Ollama 等）。可「+ 创建」多行实例，每行填写 IP 地址、端口、权重。

| 字段 | 必填 | 默认值 | 校验规则 | 说明 |
| --- | --- | --- | --- | --- |
| IP 地址 | 是 | 空 | 必须为合法 IPv4 或 IPv6 格式；实例间 IP 不能重复 | 后端实例地址 |
| 端口 | 是 | `80` | 1-65535 的整数 | 后端服务端口 |
| 权重 | 是 | 首行 `100`，新增行 `0` | 0-100 的整数 | 按权重分配流量，所有实例权重之和需等于 100 |

### 服务商域名模式

直接对接公有云模型服务商。只填一个服务商域名（如 `api.deepseek.com`），端口默认使用 443，权重固定为 100。

| 字段 | 必填 | 校验规则 | 说明 |
| --- | --- | --- | --- |
| 服务商域名 | 是 | 合法域名或 IP 格式 | 如 `api.deepseek.com` |

> 注意：域名模式下不支持填写多个地址，也不能与 IP 模式混用。

### 两种模式对比

| 形态 | 适用场景 | 端口默认值 | 权重默认值 | 数量 |
| --- | --- | --- | --- | --- |
| IP | 自建机房 / 私有化部署 | 80 | 首行 100，新增 0 | 可多行，按权重分配 |
| 服务商域名 | 公有云模型服务商 | 443 | 100 | 仅一个 |

## 4.7 步骤 5：大模型配置

配置模型服务商、模型列表接口（协议 / 地址 / 路径），点击「获取」拉取模型列表并选择本集群开放的模型；如需名称转换可配置「模型重定向」；服务商需要鉴权时填写「服务鉴权 Key」。

![大模型配置](images/04-cluster-wizard-model.png)

**表单字段**：

| 字段 | 必填 | 默认值 | 校验规则 | 说明 |
| --- | --- | --- | --- | --- |
| 模型服务商 | 否 | 空 | — | 下拉选择，选项来自 `model-provider-types` 接口 |
| 模型列表接口 | 否 | `https://{实例地址}/v1/models` | URI 必须以 `/` 开头；不能包含连续斜杠；结尾不能是斜杠；不能包含非法字符 | 协议 + 实例地址（只读）+ 路径 |
| 模型 | 是 | 空 | 至少选择 1 个模型 | 点击「获取」后从下拉选择 |
| 模型重定向 | 否 | 1 行空白 | 每行原模型名称和目标模型均不能为空；原模型名称不能重复 | 原模型名称 → 转发的后端模型名称 |
| 服务鉴权 Key | 否 | 空 | 长度不超过 512 字符 | 访问模型服务的凭证。编辑时已配置 Key 会显示提示「已配置 Key，如需修改请输入新 Key；留空则保持不变」 |

> 若模型服务商为 DeepSeek / OpenAI 等公有云，除选择服务商外，通常还需填写「服务鉴权 Key」，否则点「获取」拉取模型列表可能失败。

**模型列表接口说明**：

- 接口地址由三部分组成：协议（`http://` 或 `https://`）、实例地址（只读，来自上一步实例配置）、URI 路径（默认 `/v1/models`）。
- 可点击「+添加Header」添加自定义请求头，用于模型列表接口鉴权（如 Key 填 `Authorization`，Value 填 `xxx`）。每个 Header 包含 Key 和 Value 两个字段，可添加多个。

**获取模型操作**：

点击「获取」按钮，系统调用模型列表接口拉取可用模型。按钮在未选择服务商或实例地址为空时禁用。获取成功后模型列表填充到下拉选项中，可选择本集群开放的模型。

## 4.8 步骤 6：复查&检查

汇总展示前 5 步全部配置，确认无误后点击「提交」完成创建：

![复查汇总](images/04-cluster-wizard-review.png)

**汇总面板说明**：

| 面板 | 展示内容 |
| --- | --- |
| 基础配置 | 集群名称、集群说明、协议、单个后端最大空闲连接数、会话保持（启用/停用）、哈希策略、哈希头部、请求写缓存大小、后端连接随客户端连接关闭 |
| 超时和重传 | 客户端连接空闲超时、读客户端请求Body超时、连接后端超时、读后端响应头部超时、写响应超时、集群内重试次数 |
| 被动健康检查 | 故障阈值、健康检查间隔、健康检查Host、健康检查Uri、健康检查期望的状态码 |
| 实例配置 | 实例形态（IP/服务商域名）、服务商域名或实例IP列表（地址/端口/权重） |
| 大模型配置 | 模型服务商、模型列表接口（含Header）、模型列表、模型重定向、服务鉴权Key |

> 注意：服务鉴权 Key 在复查页面会脱敏显示。

## 4.9 注意事项

- 集群名称创建后不可修改，命名建议体现业务含义。
- 修改集群配置会影响所有引用该集群的路由规则，请在低峰期操作。
- 模型列表接口不可达时「获取」会失败，可检查地址与网络后重试。点"获取"报错时，先不要怀疑系统故障，99% 是网络不通或地址填错。
- 实例权重之和必须等于 100，请合理分配各实例的权重。
- 删除集群前需先解除路由规则中的引用，否则删除会被拦截。
